This is a pure ProdOps artifact change (SKILL.md documentation update, no TypeScript code). Standard

BDD criteria; Green = update SKILL.md to satisfy them; Yellow = run all quality gates (which check

### RED evidence

Current `prodops/skills/downstream/SKILL.md` section 6b-ii failed the following BDD criteria:

- **Scenario 5:** instruction did not explicitly include `work-item-id` as a mandatory field in the
  comment body template (only present as the `gh issue comment <work-item-id>` target, not as a
  body field named `work-item-id`).
- **Scenario 4:** no instruction that trail failure (`gh issue comment` error) is non-fatal — the
  section said "obrigatório e não pode ser omitido" with no fallback guidance.
- **Scenario 1/2:** no "before advancing" language and no "phase started" entry to enable mid-flight
  partial trail diagnosis.

### GREEN evidence

Updated `prodops/skills/downstream/SKILL.md` section 6b-ii with:

1. Two-entry trail structure per phase: "started" (before invoking sub-agent) and "completed/failed"
   (before advancing to next phase).
2. Explicit mandatory fields listed: `phase-name`, `work-item-id`, `status`, `timestamp` — both in
   prose and in the comment body template.
3. Explicit rule: "A entry de conclusão deve ser postada **antes de avançar à próxima phase ou
   issue** — nunca após."
4. Explicit non-fatal rule: "Falha ao postar trail é não-fatal: se `gh issue comment` retornar erro,
   registrar aviso interno e continuar a execução normalmente."
5. Explicit note: "O trail parcial (entries de início sem entries de conclusão) é suficiente para
   diagnosticar a última phase executada em caso de interrupção mid-flight."

All five BDD scenarios are now satisfied by the updated instruction.
