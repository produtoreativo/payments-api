### Context

New feature for DS-62: handle Asaas chargeback webhook events on `POST /webhook/payments`. When Asaas sends `PAYMENT_CHARGEBACK_REQUESTED`, `PAYMENT_CHARGEBACK_DISPUTE`, or `PAYMENT_AWAITING_CHARGEBACK_REVERSAL`, the system must update the invoice status accordingly and emit domain events. No financial action is taken — tracking and event publication only. Rules: idempotency, CREDIT_CARD billingType guard, out-of-order acceptance.

2. `api/src/modules/invoices/services/invoice.service.ts` — added 3 switch cases and private `handleChargebackEvent()` method

Logic in `handleChargebackEvent()`:
- Finds the invoice by webhook payload (by providerPaymentId or externalReference)
- Rejects with `logger.warn` if `billingType !== 'CREDIT_CARD'` (no status change)
- Skips if status is already the target (idempotency at handler level; raw event deduplication via `saveRawProviderEvent`)
- Updates invoice to target status
- Emits domain event with `invoiceId`, `orderId`, `tenantId`, `amount`, `occurredAt`
