## 2026-08-05 — Finish phase refinement: sub-steps and quality gates (issue #11)

**Correlation-id:** `4a9e4c58-8efd-49aa-8b9b-a69f59ab06a4`
**Branch:** `refine/11-finish-v2` (derived from `master`)
**Issue:** #11
**Origin:** cherry-pick from `refine/11-finish`, whose base (`chore/anthropic`) fell 90 commits behind

### What changed?

Finish phase refinement on two fronts.

**Structure.** Finish now has three invocable steps (`validate`, `review`,
`request`) plus a publish step, each with a single responsibility and an explicit
boundary of what it does **not** do — so each step is auditable in isolation. The
phase artifacts (`README`, `done-criteria`, `quality-gates`) and the Copilot
prompts were created.

**Gates.** Three new gates, all `blocks: auto_merge_only` — they disarm
auto-merge, never manual merge:

| Gate | Script | Criterion |
|---|---|---|
| `coverage` | `scripts/check-coverage-threshold.sh` | branches ≥ 100% |
| `dependencies` | `scripts/check-dependencies.sh` | Snyk, severity ≥ high |
| `sast` | `scripts/check-sast.sh` | local SonarQube, ephemeral container |

In addition, the commit workflow now enforces the whole subject within 72
characters (the regex measured only the text after `type(scope): `, letting the
prefix push the real subject past the limit) and gained scope-case and full-stop
rules.

### Why?

The Finish phase bundled validation, pipeline inspection, and PR creation into a
single block with no auditable boundaries. The coverage, dependencies, and SAST
gates did not exist: there was no local verification equivalent to the pipeline
before pushing, and no objective criterion disarmed auto-merge when quality did
not hold up.

### Fixes surfaced by the first real run of the gates

This was the first time all three gates ran end to end. Two defects of our own
surfaced and were fixed in the same session.

**1. `validate` declared a narrower scope than it executed** (`3cde6fc6`). The
*Inputs* section of `finish/steps/validate/SKILL.md` listed only `gates.lint`,
`gates.acceptance`, `gates.build`, and `gates.no_mocks`. That list predated the
coverage, dependencies, and sast gates, which were added to the step body but
never to the contract. Concrete consequence: the `finish-agent` read *Inputs* as
the scope, ran four gates, and reported PASS while three never executed. All
seven gates are now named, with a note that `blocks: auto_merge_only` governs
what a gate **disarms**, not whether it **runs**.

**2. SAST failed on coverage it does not measure** (`cfa8e6a1`). `check-sast.sh`
used the server's default quality gate ("Sonar way"), which carries
`new_coverage >= 80`. Since the scanner receives no coverage report in this flow,
Sonar read 0.0% and failed a codebase with 0 violations and 0 duplication — a
false negative that masked the security verdict.

The fix provisions a dedicated gate (`prodops-sast`). Non-obvious detail: a newly
created gate is **not empty** — SonarQube pre-populates it with CAYC ("Clean as
You Code") conditions, `new_coverage` among them. The first attempt merely added
conditions and kept failing; the coverage conditions had to be **deleted** via
`delete_condition`. CAYC's `new_security_hotspots_reviewed` was kept on purpose —
it is legitimate security analysis.

Coverage remains the exclusive responsibility of `gates.coverage`, which is
strictly stricter: branches at 100% over the whole codebase, versus lines at 80%
over new code only.

**3. `validate-manifest.sh` failed on every branch** (`a1d49df1`, `5d8e4e17`).
The `cards` path uses the `<version>` placeholder, which only resolves once a
concrete iteration exists — it can never match as written. It lost its
`# optional` marker during a reorganization and started being enforced as a fixed
path, turning the gate into a guaranteed failure. With the marker restored the
script exits 0, and the `continue-on-error` that silenced it in `pr-gates.yml`
was removed — the flag had stopped working around a bug and started suppressing a
working gate.

### Open blockers

Both require `admin` on the repository and cannot be resolved by this session
(token has `admin: false`).

1. **No `required_status_checks` on `master`.** The active rules are only
   `copilot_code_review`, `deletion`, and `non_fast_forward`. No status check

   missing branch protection as a blocker, which is why the flow stopped before
   pushing and opening the PR.
2. **`SNYK_TOKEN` not registered.** Until it exists, the `dependencies` gate
   exits 2 in any environment.
