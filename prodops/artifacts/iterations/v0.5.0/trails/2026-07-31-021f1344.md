### RED Phase

O spec de aceitação `api/test/api-token.acceptance.e2e-spec.ts` já existia com 11
testes cobrindo os cenários BDD 1–5 (token válido, ausente, inválido, revogado,
API_TOKEN_LOCAL). Foram adicionados 7 novos testes para os cenários de
observabilidade (BDD 4, 2, 3, 1 ao nível de evento), isenção de webhook (BDD 6)
e token ausente de respostas (BDD 7).

O único teste que falhou por comportamento ausente foi:

```
FAIL test/api-token.acceptance.e2e-spec.ts
  ● Eventos de observabilidade › token revogado emite api.token.rejected com reason token_revoked

    expect(received).toBe(expected)
    Expected: "token_revoked"
    Received: "token_invalid"

      244 |       expect(evt!['reason']).toBe('token_revoked');
```

**Causa raiz:** `TokenRepository.validate()` retornava `null` tanto para token
desconhecido quanto para token revogado. O guard não conseguia distinguir os
casos e sempre emitia `reason: 'token_invalid'`.

Os demais 6 testes novos passaram imediatamente (comportamento já existia):
- `token ausente emite token_missing` — PASS
- `token invalido emite token_invalid` — PASS
- `token valido emite api.token.validated` — PASS
- `POST /webhook/payments isento de X-Api-Token` — PASS
- `token invalido nao aparece no body da resposta` — PASS
- `token ausente nao expoe token no body` — PASS

### GREEN Phase

**Mudanças de implementação:**

1. `api/src/modules/auth/token.repository.ts` — removida a linha
   `if (item.revoked === true) return null;` do método `validate()`. O repositório
   agora retorna o registro com `revoked: true` em vez de `null`, permitindo que
   o chamador distinga token desconhecido de token revogado.

2. `api/src/modules/auth/api-token.guard.ts` — adicionado bloco `if (entry.revoked)`
   após a checagem de `!entry`. Quando `entry.revoked === true`, o guard emite
   `reason: 'token_revoked'` com `tokenId` no payload do evento e lança
   `UnauthorizedException` (mesmo HTTP 401 — sem vazar informação ao cliente).

3. `api/src/modules/auth/api-token.service.ts` — comentário de clareza adicionado
   para documentar que a entrada revogada é propagada para que o guard emita o
   reason correto.

4. `api/test/api-token.acceptance.e2e-spec.ts` — 7 novos testes adicionados;
   `invoicePayload` e `eventEmitter` movidos para o escopo externo do describe;
   helper `captureEvents(emitter)` definido no escopo do módulo (sem mocks).
