## [0.1.1] — 2026-07-26

### Added

**Models**
- `EventId` branded type (`string & { [_brand]: 'EventId' }`) — UUID v7 format (RFC 9562). Prevents mixing opaque identifiers with plain strings at compile time. Generated by Event Producer; no domain semantics. (`src/models/event-id.ts`)
- `OperationalEvent` type alias for `EventInstance` — domain conceptual name vs schema-level name; identical at runtime. (`src/models/event-instance.ts`)

**CloudEvents**
- `CloudEventSource` branded type — URI-reference string per CloudEvents 1.0 §3.1. Used as the `source` field of `CloudEventEnvelope`. (`src/contracts/cloud-events.ts`)

**OperationalStateEngine**
- `deduplicate(events)` — removes events with duplicate `id`; returns new array, input not mutated. Idempotent.
- `replayUntil(events, until)` — replays events up to and including the given ISO-8601 timestamp.
- `stateHistory(events)` — produces a `StateHistory` with one `StateHistoryEntry` per state-altering event.
- `StateHistoryEntry` interface — `{ state: DerivedState; causedBy: EventInstance }`.
- `StateHistory` interface — `{ workItemId: string; entries: ReadonlyArray<StateHistoryEntry> }`.

**Examples** (`src/examples/` — not part of the public API)
- `operational-event.example.ts` — constructing a valid `OperationalEvent`.
- `cloud-event-envelope.example.ts` — encoding an `OperationalEvent` into a `CloudEventEnvelope`.
- `event-query.example.ts` — querying events for a Work Item via the `EventQuery` port.
- `operational-state-engine.example.ts` — full OSE pipeline: validate, deduplicate, order, corrections, effectiveState, stateHistory.

### Changed

- `EventInstance.id` type narrowed from `string` to `EventId` — compile-time guard against opaque-ID misuse.
- `CloudEventEnvelope.source` type narrowed from `string` to `CloudEventSource`.
- `README.md` updated to reflect all v0.1.1 contracts, OSE pipeline, telemetry split, and CloudEvents mapping.

### Not implemented (out of scope)

- RT-01 through RT-06 implementations (scheduled for subsequent milestones).
- Datadog integration.
- GitHub Projects write operations.

## [0.1.0] — 2026-07-25

Initial SDK foundation.

### Added

- Package scaffold: `package.json`, `tsconfig.json`, `README.md`.
- Enums: `Journey`, `Cycle`, `Phase`, `PhaseLifecycle`, `State`, `EventCategory`, `ProducerType`, `ConsumerType`.
- Models: `EventInstance`, `EvidenceReference`, `EventTypeId`, `EventNamespace`, `DerivedState`, `TimelineState`, `WorkItem`, `Finding`, `FindingType`, `FindingSeverity`.
- Contracts: `CloudEventEnvelope`, `CloudEventEncoder`, `CloudEventDecoder`, `EventProducer`, `EventPublisher`, `EventConsumer`, `EventQuery`, `Timeline`, `OperationalStateEngine`, `ValidationResult`, `GitHubSync`, `MetricPoint`, `MetricQueryParams`, `MetricResult`, `MetricPublisher`, `MetricQuery`, `TagProjection`, `TagSet`.
- Architectural decisions reconciled: CloudEvents 1.0 transport, UUID v7 event IDs, `<Namespace>.<Subject>.<Action>[.<Qualifier>]` event type format, Timeline as read-only logical projection, separated telemetry ports, TagProjection derives tags at publish time (not stored).
- Enum corrections vs Framework canonical sources: `EventCategory` aligned to 8 categories from `taxonomy.md`; `Cycle` = operational rhythms only; `Phase` = delivery phases (Bootstrap/Hack/…); `Journey` expanded to 5 values.
